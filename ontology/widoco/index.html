Multi-Agent System (MAS) Telemetry Ontology

Standardized MAS ontology integrating Execution, Trajectory, and Metrics blocks for observability and governance of multi-agent systems.

Architecture Overview

The MAS Ontology is organized into 8 functional blocks providing modular representation of Multi-Agent Systems. The Trajectory Block implements a 5-layer progressive enrichment architecture where each layer builds upon the previous one.

Key Concepts:

  • Structural vs Execution: Types (blueprints) vs Instances (runtime)
  • Trajectories: State machines at multiple span levels (MAS, Agent, Call)
  • Layers: Progressive enrichment (Normalized → Syntactic → Semantic → Symbolic → Causal → Governance)
  • Evaluations: Code that produces Metrics from Trajectories
  • Features: Applications built on the ontology

Trajectory Block

State machines with 5-layer progressive enrichment

State machine representation: A trajectory is a sequence of States connected by Transitions. States and transitions exist at multiple span levels (MAS level, Agent level, Call level), following the execution order.

Key Concepts

  • State: Cognitive snapshot (beliefs, goals, current plan) at a point in time
  • Transition: State change with causal explanation (why did we move?)
  • Shared States: Some states are common across multiple trajectories
  • Execution Order: Trajectories follow the temporal ordering of execution traces
  • Multi-Level: MAS has trajectory, each Agent has trajectory, each Call has trajectory

5 Progressive Layers

  1. Normalized: Raw state/transition graph from OTel traces
  2. Syntactic: Tokenization, POS tagging, parsing
  3. Semantic: Concepts, entities, relationships
  4. Symbolic: Logic, rules, formal reasoning
  5. Causal: Causal relationships explaining transitions
  6. Governance: Quality dimensions (factuality, bias, safety)

See Layers Overview for detailed documentation.

Latent Space Block

Vector embeddings for semantic analysis

States and transitions embedded as dense vectors (e.g., via sentence transformers). Enables similarity search, clustering, and anomaly detection based on semantic content.

Key Classes

  • VectorEmbedding - Dense vector representation of a State
  • VectorCluster - Hierarchical cluster of similar vectors

Independent quality dimensions applied to states/transitions. Each dimension operates orthogonally (factuality doesn't depend on bias evaluation).

  • BiasDetection - Bias identification
  • RiskAssessment - Risk scoring
  • SafetyCompliance - Safety verification

Evaluations Block

Code that creates metrics from trajectories

Evaluation engines that analyze trajectories and produce Metrics as output.

Key Classes

  • Evaluation - Base class for all evaluators
  • LLMaaJ - LLM-as-Judge: uses LLM to evaluate quality
  • StatefulEval - Trajectory-based evaluation: analyzes state sequences to assign Correctness metric to output state

Example: StatefulEval

Evaluates a complete trajectory (sequence of states + transitions) to determine if the final output state is correct. Produces Correctness metric attached to the output state.

Features Block

Applications built on top of the ontology. Leverage trajectory layers and metrics to provide actionable insights.

  • Anomaly - Semantic deviations from normal behavior

Layers Overview

The Trajectory Block implements a 5-layer progressive enrichment architecture. States and transitions exist at multiple span levels (MAS, Agent, Call), following execution order. Some states are shared across trajectories.

Layer 0: Normalized

Raw state/transition graph from OTel traces. Unprocessed content.

Layer 1: Syntactic

Tokenization, POS tagging, parsing, linguistic structure.

Layer 2: Semantic

Concepts, entities, relationships. NER, coreference, semantic roles.

Layer 3: Symbolic

Logic, rules, formal reasoning. FOL expressions, constraints.

Layer 4: Causal

Causal relationships between states. Why transitions occur.

Layer 5: Governance

Quality dimensions: factuality, bias, risk, safety, compliance.

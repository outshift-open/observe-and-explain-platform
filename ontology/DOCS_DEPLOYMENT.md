# OXP Ontology Documentation Deployment

This repository automatically generates and deploys documentation for the **MAS** and **Metrics** ontologies to GitHub Pages, via `.github/workflows/deploy-docs-multi.yml`.

`semantic`, `analysis`, and `insight` are bundled in the Python package and validated in CI but are **not yet part of this deployment** — the workflow only builds `mas` and `metrics` today.

## 📚 Documentation Formats (per ontology)

For each of `mas` and `metrics`, three formats are generated side by side:

### 1. Widoco
- **Path**: `/mas/widoco/`, `/metrics/widoco/`
- Standard W3C-compliant OWL documentation, generated by Widoco v1.4.25 (JDK 17 build, downloaded and cached by the workflow — the JAR is **not** committed to the repo)

### 2. WebVOWL
- **Path**: `/mas/webvowl/`, `/metrics/webvowl/`
- Interactive graph visualization. The workflow builds one shared WebVOWL 1.1.6 instance from source (npm) and copies it into each ontology's folder, patching the default-loaded JSON file per ontology (`generate_webvowl_json_generic.py`)

### 3. LODE
- **Path**: `/mas/lode/`, `/metrics/lode/`
- Lightweight HTML via `scripts/generate_lode_html.py` (a local generator, not the w3id.org LODE web service). The step is best-effort — it's allowed to fail without failing the build (`|| echo "LODE generation skipped"`)

A landing page at `docs/index.html` (generated inline in the workflow) links to both ontologies' Widoco/WebVOWL/LODE pages and shows the deployed version.

There is currently no "comprehensive"/custom documentation format and no single merged doc site — each ontology gets its own Widoco/WebVOWL/LODE set under its own path prefix.

## 🚀 Deployment

Documentation is automatically generated and deployed via GitHub Actions on every push to `main` (and via manual `workflow_dispatch`).

### Workflow: `.github/workflows/deploy-docs-multi.yml`

```
Triggers: push to main, manual workflow_dispatch
Steps:
  1. Setup Python 3.11, Java 17 (Widoco), Node.js 18 (WebVOWL build)
  2. Download + checksum-verify + cache the Widoco JAR
  3. Resolve the version to embed (task-equivalent: scripts/version_manager.py get / get-full)
  4. Generate MAS docs: Widoco, WebVOWL JSON (generate_webvowl_json_generic.py), LODE
  5. Generate Metrics docs: Widoco, WebVOWL JSON, LODE
  6. Build one shared WebVOWL instance from source and copy+patch it into docs/mas/webvowl/ and docs/metrics/webvowl/
  7. Write docs/index.html (landing page, inline in the workflow)
  8. Upload the docs/ directory as a Pages artifact and deploy
```

### Prerequisites

**Repository Settings**:
1. Go to Settings → Pages
2. Source: GitHub Actions
3. Save

**Required files** (all present in this repo):
- `src/oxp_ontology/mas-ontology.ttl`, `src/oxp_ontology/metrics-ontology.ttl`
- `scripts/generate_webvowl_json_generic.py`
- `scripts/generate_lode_html.py`
- `scripts/version_manager.py`

The Widoco JAR is **downloaded and checksummed at CI time** (not committed) and cached by `actions/cache` keyed on `widoco-1.4.25-jdk17`.

## 🛠️ Local Development

### Quick single-ontology preview

```bash
./scripts/generate_all_docs.sh
python3 -m http.server 8000 --directory docs
# Open: http://localhost:8000
```

This is a convenience script for previewing `mas-ontology.ttl` docs locally. It builds a single flat `docs/{widoco,webvowl,lode}/` layout (not the per-ontology `docs/mas/`, `docs/metrics/` layout that CI actually deploys), and downloads its own copy of Widoco/WebVOWL if missing.

### Generate one ontology's docs manually

```bash
# Widoco
java -jar widoco.jar \
  -ontFile src/oxp_ontology/mas-ontology.ttl \
  -outFolder docs/mas/widoco \
  -rewriteAll -includeAnnotationProperties -webVowl

# WebVOWL JSON
python3 scripts/generate_webvowl_json_generic.py \
  src/oxp_ontology/mas-ontology.ttl \
  docs/mas/webvowl/data/mas-ontology.json \
  "MAS Ontology" \
  "https://outshift-open.github.io/oxp-ontology/mas"

# LODE-style HTML
python3 scripts/generate_lode_html.py src/oxp_ontology/mas-ontology.ttl docs/mas/lode/index.html
```

Swap `mas-ontology.ttl` for `metrics-ontology.ttl` (and the paths/names) to build the Metrics docs the same way.

## 🔧 Troubleshooting

### Widoco JAR download fails
The workflow verifies a SHA-256 checksum after downloading; a checksum mismatch fails the build rather than silently using a corrupted JAR. If GitHub's release asset changes, update the checksum in `deploy-docs-multi.yml`.

### WebVOWL not loading
- Check that `docs/<ontology>/webvowl/data/<ontology>-ontology.json` exists and is valid WebVOWL JSON
- Check the browser console for errors

### LODE step skipped
`generate_lode_html.py` is allowed to fail (`|| echo "LODE generation skipped"`) — check the workflow log for the actual Python traceback if the LODE page is missing.

### GitHub Pages not updating
- Check the Actions tab for the `deploy-docs-multi.yml` run status
- Verify Settings → Pages → Source: GitHub Actions
- Check the deployment environment URL in the job summary

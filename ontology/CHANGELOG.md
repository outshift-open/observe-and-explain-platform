# Changelog

All notable changes to the OXP Ontology will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.1] - 2026-09-24

### Changed
- **`spanId`/`parentSpanId` moved to `ExecutionElement`** (`optional`/`sh:Info`), broadening
  them from `CapabilityCall`-only (where `spanId` was `mandatory`/`sh:Violation`) so `Session`,
  `MASCall`, and `AgentCall` can also carry OTel span linkage.
- **`hasProcessingCall`** domain/`sh:targetClass` broadened from `AgentCall` to
  `AgentCall`∪`MASCall`, so a `MASCall` can directly denormalize a `ProcessingCall` it contains.
- **Pydantic KG models now reject unknown fields** (`extra="forbid"` via `KGBase`), catching
  typos/renamed properties at construction time instead of silently dropping them.

[2.0.1]: https://github.com/cisco-eti/oxp-ontology/compare/v2.0.0...v2.0.1

## [2.0.0] - 2026-09-17

### Breaking
- **Namespace consolidation**: `metrics:` and `analysis:` properties/classes
  merged into the shared `mas:` namespace (the file split across
  `mas-ontology.ttl`/`metrics-ontology.ttl`/`analysis-ontology.ttl`/
  `semantic-ontology.ttl`/`insight-ontology.ttl` is purely for file-size
  readability now, not independent module identity). A handful of names
  collided and were renamed on merge (e.g. `metrics:provider` →
  `mas:metricProvider`).
- **`otel-ontology.ttl` removed**, along with `embedding-ontology.ttl`,
  `impact-assessment-ontology.ttl`, `interpretability-ontology.ttl`, and
  `waste-estimation-ontology.ttl`. The bundled ontology set is now exactly
  five files: `mas`, `semantic`, `metrics`, `analysis`, `insight`.
  `scripts/version_manager.py`'s tracked components changed to match
  (`otel` → `semantic` + `insight`).
- **New shared `mas:Element` root class** (`id`/`name`) under
  `StructuralElement`/`ExecutionElement`/`TrajectoryElement`/
  `AnalysisElement` — several report fields lost their per-class name
  prefix as a result (e.g. `consistencyMean` → `mas:mean`,
  `anomalyScores` → `mas:scores`), since they now inherit identity from
  the shared base instead of repeating it.
- **`mas-shapes.ttl` is no longer committed.** It's fully generated by
  `scripts/generate_shacl_shapes.py` from the ontology files (exactly like
  the Pydantic models under `models/nodes|edges/`) and is regenerated by
  CI before tests/build. Hand-written SHACL that the generator can't
  produce (SPARQL-based multi-node constraints, `sh:class` checks on a
  property's subjects/objects) now lives in the new, committed
  `mas-shapes-custom.ttl`, loaded alongside it everywhere shapes are used

### Added
- **State/Transition chain rules** (`mas-shapes-custom.ttl`): a Session's
  initial/final `State` must be shared with at least one other execution
  node (`SessionInitialStateSharedShape`/`SessionFinalStateSharedShape`) —
  i.e. the boundary state the Session claims must also be claimed by
  whichever `AgentCall`/`ProcessingCall` actually starts/ends it, not held
  by the Session alone. `Transition` fan-in/fan-out (multiple inputs,
  multiple output states) is explicitly supported, not constrained.
- **Conditional `aboutMetric` requirement**: an `AnalysisElement` with
  `dataType = 'metric'` must carry `aboutMetric`
  (`AnalysisElementAboutMetricShape`, standard core-SHACL "if A then B" via
  `sh:or`/`sh:not` — no SPARQL needed for this one).
- **`scripts/generate_shacl_shapes.py`** — auto-generates `mas-shapes.ttl`'s
  class-level `sh:NodeShape`s, `sh:node` parent-shape inheritance mirroring
  `rdfs:subClassOf`, and bare `sh:property` references to each class's own
  properties (each already a self-contained `sh:PropertyShape` declared
  inline in the ontology files).
- **`scripts/inject_shacl_into_properties.py`** — one-off/ongoing migration
  tool that dual-types a bare `owl:DatatypeProperty`/`owl:ObjectProperty`
  declaration as `sh:PropertyShape`, injecting placeholder
  `sh:minCount`/`sh:severity` for a human to tune. Idempotent — safe to
  re-run after adding new properties.
- **`scripts/generate_webvowl_json_merged.py`** — merges all five ontology
  files into one WebVOWL JSON graph for a single comprehensive visual
  review (`owl:unionOf` synthetic nodes, `rdfs:subClassOf` edges, and
  `owl:DatatypeProperty` ranges via WebVOWL's separate `"datatype"` array).
- **`scripts/generate_models.py` reworked** to make the generated Pydantic
  models reflect the ontology's own SHACL constraints instead of treating
  every field as an optional string-defaulting-to-`None`:
  - A property is now genuinely `Field(...)`-required (bare type, no
    default) when its shape is `sh:minCount >= 1` with `sh:severity
    sh:Violation` (the "mandatory" tier). "Recommended" (`sh:Warning`) and
    "optional" (`sh:Info`) properties stay optional — missing one should
    warn via `verify_kg_object()`, not block object construction outright.
  - Optional fields get a type-safe empty default instead of `None`/
    `Optional[X]` (`""` for `str`, `0`/`0.0`/`False` for `int`/`float`/
    `bool`, `[]`/`{}` for `list`/`dict`) — a caller can rely on the field
    always holding a real value of its declared type. `datetime`/`date`
    are the one exception (no sensible "empty timestamp"), so those stay
    `Optional[...] = None`.
  - `owl:ObjectProperty` values (relationships) are no longer duplicated as
    `list[str]` attributes on the node itself — they're already generated
    as their own `KGEdge` classes under `models/edges/`, which is the only
    place a relationship lives now.
  - A class's own `rdfs:comment` is emitted as a wrapped Python comment
    under the class line, not as a spurious `comment` field. A class-level
    annotation with a fixed value (e.g. `mas:layer`) is emitted as a plain
    `ClassVar[str]` class constant, not a settable/`Optional` field.
  - A property's own `rdfs:comment` becomes the generated field's real
    `Field(..., description=...)` text, instead of a generic "Datatype
    property from ontology" placeholder.

### Fixed
- **`verification.py`**: `_shapes_graph()` never loaded the ontology files,
  only the shapes files — so `mas-shapes.ttl`'s bare `sh:property <iri>`
  references (which resolve against the property's own inline
  `sh:PropertyShape` in the ontology files) failed outright rather than
  validating. Now loads both.
- **`verification.py`**: every instance validated via `verify_kg_object()`
  spuriously failed a phantom missing `mas:id` — `id` is consumed to build
  the RDF subject URI and was excluded from the field-serialization loop,
  but `mas:id` is also its own mandatory (`sh:minCount 1`, `sh:Violation`)
  property on `mas:Element`, so it still needs to be asserted as a triple.
- **`verification.py`**: a failing `sh:node`-nested shape (used throughout
  `mas-shapes.ttl` for class-hierarchy inheritance) is wrapped by pyshacl in
  an outer `NodeConstraintComponent` result whose own `sh:resultSeverity` is
  always `sh:Violation`, regardless of the real severity of whatever failed
  inside it — so a missing Warning-only (recommended) property anywhere up
  an inheritance chain (e.g. `mas:name`) incorrectly failed `conforms` for
  every subclass. This was flagged as a known gap in 1.1.6's changelog;
  `verify_kg_object()` now skips these wrapper results (identified by
  having `sh:detail` children) and counts only the leaf-level result that's
  already present independently, which carries the correct severity.
- **`verification.py`**: a type-safe empty default (`""` for `str`, `{}` for
  `dict`, in place of `None`) still satisfies `sh:minCount 1` — it's a real
  value, just an empty one — so serializing it into the instance graph
  would silently defeat a "missing recommended property" check. An empty
  value of either kind is now excluded from the graph the same way `None`
  already was (an empty `list` needed no equivalent fix: it naturally adds
  zero triples already).
- **`mas:description`** was declared three times (`StructuralElement`,
  `SemanticGroup`, `Insight`) sharing one property IRI — its `sh:severity`
  disagreed across two of the three (`sh:Info` vs `sh:Warning`), and once
  `generate_models.py` started surfacing a property's own `rdfs:comment` as
  the generated field's description (see Added), its *comment text* turned
  out to disagree across all three too. SHACL has no way to give one
  `PropertyShape` a different severity or comment per `sh:targetClass`, so
  pyshacl/the generator picked one arbitrarily for all of them every time.
  Consolidated to a single declaration (in `mas-ontology.ttl`) listing all
  three as `sh:targetClass` values, rather than three near-duplicate
  declarations that had to be kept in lockstep by hand.
- **`mas:embeddingModel`**: declared twice (`Embedding`, `SemanticGroup`)
  with the same severity but a disagreeing `rdfs:comment` — same failure
  mode as `mas:description` above, minus the severity mismatch. Unified the
  comment text (kept as two declarations, since their `sh:targetClass`
  values are unrelated classes rather than a natural single-property fit).
- **`mas:hasAgentCall`/`mas:belongsToMASCall`**: bidirectional pair missing
  `owl:inverseOf`, flagged by the `schema-directionality` lint check.

## [1.1.6] - 2026-09-15

### Added
- **`oxp_ontology.verification.verify_kg_object()`** — new instance-level
  SHACL conformance check for a single constructed KG node/edge object
  (as opposed to `validate_bundled_ontologies()`, which lints the ontology
  TTL files themselves). Builds a one-instance RDF graph from the object's
  populated fields and validates it against the bundled SHACL shapes.
  Returns a `KGVerificationReport` (`conforms`, `violations`, `errors`,
  `warnings`); `OntologyValidationError` wraps a non-conforming report for
  callers that want to raise. Only Violation-severity results (mandatory
  properties) affect `conforms` — Warning-severity results (recommended
  properties) are surfaced but never block. Intended for oxp-lib's `api`
  layer to call before writing a worker-constructed report/insight object
  to the graph database.
- **New `verify` extra** (`pip install oxp-ontology[verify]`) — pulls in
  `pyshacl`, required by `verify_kg_object()`. Not part of the `models`
  extra since most consumers of the generated Pydantic models never need
  to run SHACL validation themselves.
- **`mas-shapes.ttl` (companion comment-versioned v1.8.0)** — SHACL shapes
  for the group-scoped analysis reports added in 1.1.5:
  `SemanticAnalysisReportShape`, `ConsistencyReportShape`, `AnomalyReportShape`,
  `NormalBehaviourReportShape`, `InsightShape`. Each concrete report shape
  repeats its inherited `groupId`/`dataType`/`groupNodeHash` constraints
  directly rather than factoring them out via `sh:node` (see Fixed).

### Fixed
- **`mas-shapes.ttl`**: discovered (while building the new report shapes)
  that composing a shape via `sh:node` collapses the *inner* shape's
  per-property severities: pyshacl wraps a failing nested `sh:node` shape in
  an outer `NodeConstraintComponent` result whose own severity defaults to
  `sh:Violation` regardless of the inner property's declared severity — so
  a missing Warning-only (recommended) property inside a `sh:node`-nested
  shape incorrectly fails `conforms`, exactly as if it were mandatory
  (verified against pyshacl 0.30). The new report shapes avoid `sh:node`
  entirely for this reason. **Not fixed**: the existing `sh:node`-composed
  shapes elsewhere in this file (e.g. `*Call` shapes inheriting
  `ExecutionElementShape`) likely have the same latent issue for their
  Warning-severity properties — out of scope here, flagged for a follow-up.
- **`mas-shapes.ttl`**: a `sh:property` shape with `sh:severity sh:Warning`
  but no `sh:minCount` never actually fires when the property is absent —
  `sh:datatype` alone is vacuously satisfied when there are zero values to
  check. All new Warning-severity properties added in this release pair
  `sh:severity sh:Warning` with `sh:minCount 1` so "recommended" properties
  are actually enforced (as warnings) rather than silently inert. **Not
  fixed**: pre-existing Warning-severity properties elsewhere in this file
  appear to have the same gap — out of scope here, flagged for a follow-up.

## [1.1.5] - 2026-09-15

### Added
- **`analysis-ontology.ttl`** — group-scoped analysis report classes, computed
  by the oxp-lib analysis-worker pipeline over a `SemanticGroup` of sessions
  (as opposed to a single session/call):
  - `SemanticAnalysisReport` — abstract base (subclasses `AnalysisArtefact`), with
    the properties common to every group report: `groupId`, `dataType`,
    `reportMetadata`, `reportOtherValues`, `groupNodeHash`.
  - `ConsistencyReport` — statistical consistency summary (`consistencyMean`,
    `consistencyMinValue`, `consistencyMaxValue`, `consistencyConfidenceInterval`,
    `consistencyConfidenceIndicator`) across a group's sessions, for one
    analysis layer (text/graph/metric).
  - `AnomalyReport` — inlier/outlier classification summary for one metric
    across a group's sessions (`anomalyMetricName`, `anomalyInliersValues`,
    `anomalyOutliersValues`, `anomalyScores`, `anomalyThreshold`).
  - `NormalBehaviourReport` — representative/centroid summary of normal
    behaviour for one analysis layer (`normalBehaviourRawResult`,
    `normalBehaviourCentroid`, `normalBehaviourRepresentativeSample`,
    `normalBehaviourRepresentativeProcessedSample`).
  - `Insight` — a rendered, catalog-templated insight attached to a target KG
    node (`insightTemplateId`, `insightName`, `insightDescription`,
    `insightLabels`, `insightScope`, `insightPriority`, `insightTargetNodeId`,
    `insightCreatedAt`), produced by the intelligence-worker.
  - Relationships: `hasConsistencyReport`, `hasAnomalyReport` (domain
    `SessionGroup ∪ Session ∪ Metric`), `hasNormalBehaviourReport`, and
    `hasInsight` (domain `Session ∪ MAS ∪ Agent ∪ SessionGroup`).

### Changed
- **`analysis-ontology.ttl`** — `PRIOR_VERSION_OPTIONAL` now covers this file
  (first real content release; no prior version to reference).

### Removed
- **`analysis-ontology.ttl`** — the per-call `AnomalyReport` class
  (`anomalyKind`, `anomalyScore`, `anomalyThreshold`, `anomalyContext`,
  `anomalyAffectsCall`). It had no producer anywhere in oxp-lib. Superseded
  by the group-scoped `AnomalyReport` above, which models what
  anomaly-detection-worker actually computes: a statistical inlier/outlier
  summary over a whole `SemanticGroup`, not a single-call event.

### Fixed
- **`scripts/generate_models.py`** — datatype properties with an
  `xsd:dateTime`/`xsd:date` range generated a model referencing `datetime`/
  `date` without importing them. Latent bug (no prior class used those
  ranges); now imports only what a given class's fields actually need.

## [1.0.0-rc1] - 2026-02-25

### Added
- **`interpretability-ontology.ttl` v1.1.0** — new file for trajectory enrichment
  layers (Syntactic → Semantic → Symbolic → Causal), latent-space representations
  (`VectorEmbedding`, `SemanticDisplacement`), trajectory transformations,
  qualitative evaluation taxonomy, and analytical applications.
  Declares `inputLayer`, `outputLayer` as `owl:AnnotationProperty`; absorbs
  `clustersInto` and `connectsCluster` (moved from `mas-ontology.ttl` v1.7.0).
- **`mas-ontology.ttl` v1.0.0-rc1** — see sub-entries below.
- **`mas-shapes.ttl` v1.0.0-rc1** — see sub-entries below.
- **`scripts/validate_ttl.py`** — permanent validation script covering Turtle syntax,
  `owl:versionInfo`, `owl:priorVersion`, class/property presence,
  SHACL NodeShape count, and RDF-level stale-URI check (immune to false positives
  from occurrences in `rdfs:comment` literals).

#### `mas-ontology.ttl` (v1.0.0-rc0 → v1.0.0-rc1)

**Milestone A** — interpretability split: trajectory enrichment layers, evaluation
taxonomy, and analytical applications moved to `interpretability-ontology.ttl`.

**Milestone B** — identity model: `callId` added as mandatory MERGE key; `executionId`
downgraded to recommended; `sessionId` domain broadened to `Session∪State∪Transition`;
`runId` added as optional provenance attribute.

**Milestone C** — pipeline metadata: `kindBase`, `masUri`; `agentId` domain broadened
to `Agent∪ExecutionElement`; `toolOutput`, `processingOutput`, `sourceCallId`,
`realisesCallId` added; `CallAnnotation` class + properties added (§16).

**Milestone D** — spelling: `realisesCallId` → `realizesCallId` (American spelling,
consistent with `edge_type: "realizes"` in normalize_manifold.py);
`agentId :requirement` downgraded to `"recommended"` on `ExecutionElement`.

**Milestone E** — dead properties removed: `sequenceNumber` (total-order index is
wrong for parallel traces), `allSpanIds`, `mainSpanId` (no producer; `sourceSpanId`
covers the use case).

**Milestone F** — OWL well-formedness: declared 6 formerly-undeclared
`owl:AnnotationProperty` (`block`, `baseColor`, `icon`, `layer`, `shape`,
`spanLevel`); removed latent-space forward-reference block (`embedsAs`,
`clustersInto`, `connectsCluster`) — moved to `interpretability-ontology.ttl`
whose classes they reference; removed `:VectorEmbedding` from `:status` domain.

#### `mas-shapes.ttl` (v1.0.0-rc0 → v1.0.0-rc1)

**Milestones S1–S2** — initial SHACL coverage: `SessionShape`, `ExecutionElementShape`,
`ToolCallShape`, `ProcessingCallShape`, `StateShape`, `TransitionShape`,
`AgentShape`, `TaskCallShape`, `MemoryCallShape`, `CallAnnotationShape`, `DPPhaseShape`.

**Milestone S3** — critical bug fix: `SessionShape` no longer inherits
`ExecutionElementShape` (that inheritance imposed a `callId` Violation on every
Session node — wrong MERGE key; Sessions use `sessionId`). Removed stale
`mas:input`/`mas:output` warnings on `SessionShape`.

**Milestone S4** — property completions: `toolOutput Warning`, `processingOutput Warning`,
`sourceCallId Warning`, `realizesCallId Warning` added.

### Fixed
- 3 multi-line single-quoted strings in `interpretability-ontology.ttl` and
  `metrics-ontology.ttl` converted to triple-quoted literals (`"""..."""`).
  Turtle single-quoted strings cannot span multiple lines.
- `connectsCluster rdfs:range` written as `mas:Entity` instead of `:Entity`
  (interpretability namespace) — corrected.

## [1.1.0-rc1] - 2026-02-24

### Breaking changes
- **`mas-ontology.ttl`**: Properties `invokesLLM` and `invokesTool` with domain
  `LLMCall → LLM` / `ToolCall → Tool` (structural type links) renamed to
  `ofLLMType` / `ofToolType`. Properties with domain `AgentCall → LLMCall` /
  `AgentCall → ToolCall` (execution shortcuts) keep the original names.
- **`mas-ontology.ttl`**: `:provider` and `:model` on `mas:Metric` domain
  renamed to `:evaluationProvider` / `:evaluationModel` to resolve URI collision
  with `:provider` on `mas:LLMCall` domain.
- **`mas-ontology.ttl`**: `:outputOf` property removed — it was declared as
  `owl:inverseOf :leadsTo`, making it identical to `:inputTo` (redundant inverse
  chain). Use canonical `:fromState` / `:toState` (§14) instead.

### Fixed
- **Property duplication (#1)**: Removed duplicate declarations of
  `promptTokenCount`, `completionTokenCount`, `totalTokenCount`,
  `cacheReadTokenCount`, `modelName`, `modelTemperature`, `responseId`,
  `finishReason`, `provider` (LLMCall), `toolArguments`, `toolCallId` from the
  §5 Metrics block. All are now declared exactly once in §13/§14 with
  `:requirement` annotations.
- **Class-level dependency triples (#4)**: Removed `:dependsOn :Correctness`
  from `ResponseCompleteness` and `:feedsInto :ResponseCompleteness` from all
  `Evaluation` subclasses. These triples belong on *instances*, not class
  declarations.
- **Dangling Bias URIs (#6)**: Removed `mas:Concept_Political`,
  `mas:Concept_Gender`, `mas:Concept_Racial`, `mas:Concept_Cultural` URI
  references from `Bias` subclasses in `metrics-ontology.ttl`. Semantic anchor
  is now captured exclusively via `:templateParameter` (xsd:string).

### Changed
- **OTel block consolidation (#3)**: `mas-ontology.ttl` §4 class definitions
  (`Span`, `Trace`, `OTelSession`, `traceId`, `spanId`, `parentSpanId`,
  `spanKind`, `hasTrace`, `containsSpan`) removed. `otel-ontology.ttl` is now
  the canonical source. `mas-ontology.ttl` adds `owl:imports otel` and retains
  only the MAS-bridge properties (`normalizesTo`, `hasOTelSession`,
  `mainSpanId`, `allSpanIds`).
- **Properties re-added to §13** after §5 removal:
  `provider`, `finishReason`, `responseId`, `cacheReadTokenCount`,
  `modelTemperature` — all now carry `:requirement` annotations.
- **`otel-ontology.ttl` description** updated to reflect canonical role.
- All three ontology files: `dcterms:modified` updated to 2026-02-24.

### Added
- **§15 Design Pattern Vocabulary** in `mas-ontology.ttl`:
  - `DesignPatternScheme` (`skos:ConceptScheme`) with five pattern individuals:
    `ReActPattern`, `ChainOfThoughtPattern`, `PlanExecutePattern`,
    `EventLoopPattern`, `AccumulatorPattern` (keyed to `dp_id` notation from
    agent-runtime).
  - `DPPhaseScheme` (`skos:ConceptScheme`) with eight phase individuals:
    `DECIDE`, `ACT`, `OBSERVE`, `FINALIZE`, `INTERRUPT`, `COLLECT`, `READY`,
    `WAIT_EVENT` — aligned with `DPPhase` enum in `agent_runtime.contracts.dp_contract`.
  - `mas:dpPhase` datatype property on `ExecutionElement` linking OTel span
    attribute values to `DPPhaseScheme` notations.
- **`owl:priorVersion`** declared on all three ontology headers.

- **MAS Ontology**: Initial release of the Multi-Agent System (MAS) Telemetry Ontology (`mas-ontology.ttl`).
